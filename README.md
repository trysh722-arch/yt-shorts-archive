# 유튜브 최신 Shorts 선반 자동 캡처 → 구글시트 아카이브

시트에 키워드를 적어두면, 매일 **오전 8시·오후 8시**에 깃허브 서버가 그 키워드로 유튜브를 검색해서
`OOO의 최신 Shorts 동영상` 선반을 `더보기`로 전부 펼친 화면을 캡처하고, 시트에 한 줄씩 쌓는다.

**내 PC는 꺼져 있어도 된다.** 캡처도 기록도 전부 깃허브 서버에서 돈다.

## 시트 생김새

| 탭 | 내용 |
|---|---|
| `_키워드` | **여기에 키워드를 적는다.** A=키워드 B=사용(비우거나 Y면 켬, N이면 끔) C·D=마지막 실행 결과 |
| `<키워드>` | 회차마다 1행. 캡처시각·선반제목·Shorts수·**썸네일 이미지**(검색 결과 맨 위 `Shorts` 선반 5개)·선반 전체 링크·검색 상단 링크·**비고** |
| `<키워드>_목록` | 회차마다 Shorts 개수만큼. 제목·조회수(숫자)·영상ID·새동영상 표시·링크 |

키워드를 새로 적으면 **다음 회차에 탭 두 개가 저절로 생긴다.** 미리 만들 것 없다.

**채널 선반이 없는 검색어**(예: "배민" 은 로그인 없는 화면에 "OOO의 최신 Shorts 동영상" 선반이 안 붙는다)는
실패가 아니라 정상 회차로 기록된다. 그때는 검색 결과에 흩어진 일반 `Shorts` 선반 **4세트(5개×4세트)** 를
세로로 이어 붙인 1장이 "선반 전체 이미지" 자리에 들어가고, `비고` 열에 `선반 이미지 없음` 이 찍힌다.
다음 회차에 채널 선반이 생기면 그 행 `비고` 에 `선반이미지 추가` 가 찍힌다(직전 회차가 `없음` 일 때만).
유튜브가 선반마다 5개(1줄) 또는 10개(2줄)를 보여주므로 4세트의 실제 Shorts 수는 회차별 20~40개다. `_목록` 에는 그 전부가 들어간다.

`_목록` 탭이 있어서 조회수 증가 추이나 신규 업로드를 수식으로 바로 뽑을 수 있다.
단, 유튜브가 이 선반에 업로드 날짜를 안 보여주기 때문에 **업로드 시점은 수집되지 않는다.**
대신 `새동영상` 열과 캡처시각으로 "언제 처음 목록에 등장했는지"를 알 수 있다.

## 왜 이미지가 깃허브에 있나

구글시트는 이미지 파일을 품지 못하고 `=IMAGE("주소")` 로 외부 주소를 불러올 뿐이다.
그래서 이미지 실물은 이 저장소에 `archive/<키워드>/<연도>/<시각>/` 로 쌓이고, 시트는 그걸 가리킨다.
**저장소가 공개여야 구글이 이미지를 읽어갈 수 있다.**

## 설치

사용자가 할 일은 **두 가지뿐**이고, 나머지는 `setup.py` 가 전부 한다.

### 1. 구글시트 만들고 공유 (이건 대신 못 해준다)

빈 스프레드시트를 하나 만들고, 아래 주소에 **편집자**로 공유한다.

```
cj-dashboard@madbox-354708.iam.gserviceaccount.com
```

서비스계정에 Drive 권한이 꺼져 있어 시트 생성·공유는 API로 불가능하다. 확인 완료(2026-09-14).

### 2. 깃허브 토큰 발급 (이것도 본인 계정이라 대신 못 해준다)

github.com → Settings → Developer settings → Personal access tokens → **Tokens (classic)**
→ Generate new token → scope 는 **`repo`** 와 **`workflow`** 두 개만 체크 → 생성된 문자열 복사.

### 3. 나머지는 한 줄

```
cd Desktop\클로드\yt_shorts_capture
python setup.py <토큰> <시트URL>
```

이 한 줄이 공개 저장소 생성 → 코드 push → 시크릿 2개 등록 → 첫 실행 → 결과 확인까지 다 한다.
토큰은 화면에도 파일에도 남지 않는다. 저장소 이름을 바꾸려면 세 번째 인자로 넘긴다.

## 내 PC에서 시험 삼아 돌리기

```
cd Desktop\클로드\yt_shorts_capture
copy ..\시트API\service_account.json .
set SHEET_ID=시트ID
set REPO=깃허브아이디/저장소이름
set SKIP_PUSH=1
python run.py "배달의 민족"
```

`SKIP_PUSH=1` 이면 이미지를 올리지 않으므로 시트의 썸네일은 깨져 보인다. 시트 기록 흐름만 확인하는 용도다.
캡처만 보고 싶으면 `python capture.py "배달의 민족" out`.

## 나오는 파일 (키워드 1개 1회차)

| 파일 | 보관 | 내용 |
|---|---|---|
| `01_검색상단.jpg` | 저장소 | 검색 결과 첫 화면 |
| `02_선반_접힘.jpg` | 저장소 | 접힌 채널 선반 (채널 선반이 있을 때만) |
| `03_선반_전체.jpg` | 저장소 | 더보기 펼친 채널 선반 전체 (긴 세로 1장). 채널 선반이 없으면 일반 `Shorts` 선반 4세트를 이어 붙인 것 |
| `04_Shorts상단.jpg` | 저장소 | 검색 결과 맨 위 일반 `Shorts` 선반 5개. **시트 썸네일로 쓴다** |
| `03_세트NN.jpg` | 액션 첨부 30일 | 채널 선반이 없을 때 일반 `Shorts` 선반 세트별 원본 |
| `03_선반_partNN.jpg` | 액션 첨부 30일 | 위를 화면 높이로 자른 것 |
| `items.json` `meta.txt` | 저장소 | 쇼츠 목록 원본, 캡처 로그 |

저장소에 들어가는 건 회차당 약 1.2MB (가로 1000px, 품질 82로 줄여서 보관).

## 알아둘 것

- **용량 한도.** 매회 저장하므로 키워드 1개면 1년에 약 0.9GB, 3개면 2.6GB다. 깃허브 권장은 1GB, 한계는 5GB.
  `archive/<키워드>/<연도>/` 구조라서 지난 연도 폴더를 지우면 바로 회수된다. 시트의 기록과 링크는 남는다.
- **실행 시간.** 키워드 1개당 약 2분. 무료 한도 월 2,000분이라 키워드 15개까지 여유롭다.
- **로그인 안 한 상태**로 캡처한다. 개인화가 없어 회차끼리 비교가 되지만, 내 브라우저 화면과 순서가 다를 수 있다. vidIQ 배지도 안 나온다.
- 깃허브 크론은 서버가 붐비면 몇 분 늦게 돈다. 보통 5분 이내.
- 미국 서버에서 접속하므로 `hl=ko&gl=KR` 로 한국·한국어를 강제한다. 유튜브는 **세션마다 다른 레이아웃**(격자형/목록형)을 주므로 선반은 태그가 아니라 제목 텍스트로 찾고, 못 찾으면 새 세션으로 최대 3회 다시 시도한다.
- 실패하면 `_키워드` 탭 D열에 아래 사유 중 하나가 찍힌다. 액션 첨부파일의 `99_실패화면_N.jpg` 로 그 시도의 화면을 볼 수 있다.

  | D열 사유 | 뜻 | 할 일 |
  |---|---|---|
  | `채널 Shorts 선반 없음` | 채널 선반도, 대체할 일반 `Shorts` 선반도 없다 (채널 선반만 없으면 실패가 아니라 `비고=선반 이미지 없음` 정상 회차) | 유튜브 화면이 바뀐 것. `capture.py` 점검 |
  | `레이아웃/로딩 문제` | 결과가 조금만 로드됐거나, 제목은 있는데 카드 묶음을 못 잡았다 | 다음 회차에 대개 회복. 반복되면 `capture.py` 점검 |
  | `봇체크/동의화면` | 유튜브가 확인 화면을 띄웠다 | 다음 회차에 대개 회복 |
  | `이미지 업로드 실패` | 캡처·시트 기록은 됐지만 이미지 푸시가 실패해 썸네일 대신 이 글자가 들어갔다 | Actions 로그 확인 |
  | `기타 예외: …` | 위에 해당하지 않는 오류 | 로그 확인 |
- 선반은 태그가 아니라 제목 텍스트로 찾는다: 채널 선반은 `최신 Shorts 동영상` 부분일치(`SHELF_TEXT`), 일반 선반은 정확히 `Shorts`(`TOP_TEXT`). 유튜브가 문구를 바꾸면 `capture.py` 위쪽 이 두 값을 고친다. 2026-09-15 기준값이다.
- `meta.txt` 의 `펼침확인(카드증가/간략히버튼)=YES` 는 더보기가 끝까지 펼쳐졌다는 뜻이다. 일반 `Shorts` 선반은 더보기를 눌러도 10개까지만 펼쳐지므로 4세트는 접힌 상태(5개)로 찍는다.
