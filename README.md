# 유튜브 최신 Shorts 선반 자동 캡처 → 구글시트 아카이브

시트에 키워드를 적어두면, 매일 **오전 8시·오후 8시**에 깃허브 서버가 그 키워드로 유튜브를 검색해서
`OOO의 최신 Shorts 동영상` 선반을 `더보기`로 전부 펼친 화면을 캡처하고, 시트에 한 줄씩 쌓는다.

**내 PC는 꺼져 있어도 된다.** 캡처도 기록도 전부 깃허브 서버에서 돈다.

## 시트 생김새

| 탭 | 내용 |
|---|---|
| `_키워드` | **여기에 키워드를 적는다.** A=키워드 B=사용(비우거나 Y면 켬, N이면 끔) C·D=마지막 실행 결과 |
| `<키워드>` | 회차마다 1행. 캡처시각·선반제목·Shorts수·**썸네일 이미지**·선반 전체 링크·검색 상단 링크 |
| `<키워드>_목록` | 회차마다 Shorts 개수만큼. 제목·조회수(숫자)·영상ID·새동영상 표시·링크 |

키워드를 새로 적으면 **다음 회차에 탭 두 개가 저절로 생긴다.** 미리 만들 것 없다.

`_목록` 탭이 있어서 조회수 증가 추이나 신규 업로드를 수식으로 바로 뽑을 수 있다.
단, 유튜브가 이 선반에 업로드 날짜를 안 보여주기 때문에 **업로드 시점은 수집되지 않는다.**
대신 `새동영상` 열과 캡처시각으로 "언제 처음 목록에 등장했는지"를 알 수 있다.

## 왜 이미지가 깃허브에 있나

구글시트는 이미지 파일을 품지 못하고 `=IMAGE("주소")` 로 외부 주소를 불러올 뿐이다.
그래서 이미지 실물은 이 저장소에 `archive/<키워드>/<연도>/<시각>/` 로 쌓이고, 시트는 그걸 가리킨다.
**저장소가 공개여야 구글이 이미지를 읽어갈 수 있다.**

## 설치

### 1. 구글시트 만들고 공유

새 스프레드시트를 하나 만들고, 아래 주소에 **편집자**로 공유한다.

```
cj-dashboard@madbox-354708.iam.gserviceaccount.com
```

주소창의 `docs.google.com/spreadsheets/d/` **다음에 오는 긴 문자열**이 시트 ID다. 나중에 쓴다.

### 2. 깃허브 저장소

1. **공개(Public)** 저장소를 새로 만든다.
2. 이 폴더를 push 한다.
3. Settings → Secrets and variables → Actions → New repository secret 으로 두 개를 넣는다.

   | 이름 | 값 |
   |---|---|
   | `GOOGLE_SA_JSON` | `service_account.json` 파일 **내용 전체**를 그대로 붙여넣기 |
   | `SHEET_ID` | 1번에서 확인한 시트 ID |

   서비스계정 파일은 `Desktop\클로드\시트API\service_account.json` 에 있다.
   **이 파일은 저장소에 올리지 말 것.** `.gitignore` 에 이미 걸려 있다.

4. Actions 탭 → `youtube-shorts-capture` → `Run workflow` 로 **수동 1회 실행**한다.
   - 성공하면 시트에 탭이 생기고 첫 행이 들어간다.
   - 썸네일이 깨져 보이면 1~2분 뒤 새로고침. 그래도 깨지면 저장소가 공개인지 확인한다.

### 3. 끝

이후로는 `_키워드` 탭에 줄을 추가하기만 하면 된다. 지우고 싶으면 B열에 `N`.

## 내 PC에서 시험 삼아 돌리기

```
cd Desktop\클로드\yt_shorts_capture
copy ..\시트API\service_account.json .
set SHEET_ID=시트ID
set REPO=깃허브아이디/저장소이름
set SKIP_PUSH=1
python run.py "배달의 민족"
```

`SKIP_PUSH=1` 이면 이미지를 올리지 않으므로 시트의 썸네일은 깨져 보인다. 시트 기록 흐름만 확인하는 용도다.
캡처만 보고 싶으면 `python capture.py "배달의 민족" out`.

## 나오는 파일 (키워드 1개 1회차)

| 파일 | 보관 | 내용 |
|---|---|---|
| `01_검색상단.jpg` | 저장소 | 검색 결과 첫 화면 |
| `02_선반_접힘.jpg` | 저장소 | 접힌 선반. 시트 썸네일로 쓴다 |
| `03_선반_전체.jpg` | 저장소 | 더보기 펼친 선반 전체 (긴 세로 1장) |
| `03_선반_partNN.jpg` | 액션 첨부 30일 | 위를 화면 높이로 자른 것 |
| `items.json` `meta.txt` | 저장소 | 쇼츠 목록 원본, 캡처 로그 |

저장소에 들어가는 건 회차당 약 1.2MB (가로 1000px, 품질 82로 줄여서 보관).

## 알아둘 것

- **용량 한도.** 매회 저장하므로 키워드 1개면 1년에 약 0.9GB, 3개면 2.6GB다. 깃허브 권장은 1GB, 한계는 5GB.
  `archive/<키워드>/<연도>/` 구조라서 지난 연도 폴더를 지우면 바로 회수된다. 시트의 기록과 링크는 남는다.
- **실행 시간.** 키워드 1개당 약 2분. 무료 한도 월 2,000분이라 키워드 15개까지 여유롭다.
- **로그인 안 한 상태**로 캡처한다. 개인화가 없어 회차끼리 비교가 되지만, 내 브라우저 화면과 순서가 다를 수 있다. vidIQ 배지도 안 나온다.
- 깃허브 크론은 서버가 붐비면 몇 분 늦게 돈다. 보통 5분 이내.
- 미국 서버에서 접속하므로 `hl=ko&gl=KR` 로 한국·한국어를 강제한다. 그래도 유튜브가 서버 IP를 막으면 실패할 수 있다. 실패하면 `_키워드` 탭 D열에 사유가 찍히고, 액션 첨부파일의 `99_실패화면.jpg` 로 원인을 본다.
- 유튜브가 화면 구조를 바꾸면 `capture.py` 위쪽 `SHELF_SEL`(현재 `grid-shelf-view-model`)을 고쳐야 한다. 2026-09-14 기준값이다.
- `meta.txt` 의 `완전펼침확인(간략히버튼)=YES` 는 더보기가 끝까지 펼쳐졌다는 뜻이다.
